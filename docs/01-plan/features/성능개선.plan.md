# Plan: 성능개선

> 작성일: 2026-02-19
> 상태: Draft
> 레벨: Dynamic

## 1. 배경 및 목적

vibe_board(감정 일기 앱) 코드 전반 리뷰 결과, 성능·품질 이슈 6가지를 발견.
일기 수가 늘어날수록 성능 저하가 심해지는 구조적 문제와, UX를 해치는 버그들을 함께 수정한다.

## 2. 문제 정의

| # | 심각도 | 위치 | 문제 |
|---|--------|------|------|
| 1 | 🔴 Critical | `actions.ts:194` | `getEmotionStats`가 모든 일기를 JS로 가져와 집계 → DB가 해야 할 일 |
| 2 | 🟡 Major | `actions.ts:15-21` | `auth()` + `currentUser()` 두 번 호출 → 불필요한 Clerk API 왕복 |
| 3 | 🟡 Major | `diary-detail-client.tsx:23-30` | 삭제 실패 시 사용자에게 아무 피드백 없음 |
| 4 | 🟢 Minor | `diary/page.tsx:7-8` | `EMOTION_MAP`, `Emotion` import 되어 있으나 미사용 |
| 5 | 🟢 Minor | `src/features/example/`, `src/app/example/` | 예제 코드가 프로덕션에 그대로 남아있음 |
| 6 | 🟢 Minor | `gemini.ts:33` | `gemini-flash-latest` 사용 → 버전 고정 필요 |

## 3. 개선 범위 (In Scope)

- [ ] `getEmotionStats`: Supabase RPC 또는 DB-side 집계로 교체
- [ ] `createDiary`: `currentUser()` 하나로 통합 (`auth()` 제거)
- [ ] `deleteDiary` 클라이언트: 실패 toast 알림 추가
- [ ] `diary/page.tsx`: 미사용 import 제거
- [ ] example 코드 정리 (features/example, app/example)
- [ ] Gemini 모델명 버전 고정

## 4. Out of Scope

- 페이지네이션 구현 (별도 기능)
- YouTube API 실시간 검색으로 전환
- UI 디자인 변경

## 5. 기대 효과

| 개선 항목 | 기대 효과 |
|-----------|-----------|
| DB 집계 전환 | 일기 1000개 기준 데이터 전송량 ~95% 감소 |
| Clerk 호출 통합 | 일기 작성 응답시간 ~100ms 단축 |
| 삭제 실패 피드백 | UX 개선, 사용자 혼란 방지 |
| 코드 정리 | 번들 사이즈 및 유지보수성 향상 |

## 6. 구현 우선순위

1. `getEmotionStats` DB 집계 (성능 영향 큼)
2. `createDiary` Clerk 호출 통합 (빠른 적용)
3. 삭제 실패 피드백 (UX 영향)
4. 미사용 import + example 코드 정리
5. Gemini 모델 버전 고정

## 7. 위험 요소

| 위험 | 대응 |
|------|------|
| Supabase RPC 함수 추가 시 migration 필요 | 로컬 테스트 후 적용 |
| `currentUser()` 통합 시 username 추출 로직 확인 필요 | 기존 로직과 동일하게 유지 |
